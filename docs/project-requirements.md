# 文件清理工具（桌面窗口版）项目需求文档

## 1. 文档目标

本文定义将当前桌宠形态改造成传统桌面窗口应用后的产品需求。应用使用标准 Electron 窗口承载全部功能，不再依赖透明桌宠、悬浮人物、气泡菜单或鼠标穿透交互。

文件清理算法仍由现有清理模块负责；本文重点定义窗口化产品的界面、交互、系统集成、数据管理和工程交付要求。

## 2. 产品定位

应用用于 Windows 和 macOS 桌面环境，为用户提供一个清晰、可操作、可追溯的文件清理工具。

产品应具备以下特点：

- 启动后进入标准主窗口，用户可以最大化、最小化、调整大小和关闭窗口。
- 所有主要操作通过明确的导航、按钮、表格和表单完成。
- 用户在执行清理前可以查看目标、清理级别和风险提示。
- 操作结束后可以查看结果和历史记录。
- 系统集成功能作为设置项提供，不影响主窗口的基本使用。

## 3. 信息架构

主窗口采用左侧导航或顶部标签页，至少包含以下页面：

1. **清理任务**：选择文件或文件夹、查看待处理列表、选择清理参数并开始任务。
2. **清理记录**：查询历史结果、筛选记录和删除记录。
3. **设置**：管理清理默认值、界面偏好和系统集成。
4. **关于**：显示版本、许可证、项目说明和反馈入口。

窗口标题栏显示应用名称和当前页面名称。页面切换不应丢失尚未提交的表单内容；执行中的任务切换页面后仍需持续运行，并在导航中显示进行状态。

## 4. 清理任务页面

### 4.1 目标选择

- 提供“添加文件”“添加文件夹”和“从资源管理器打开”入口。
- 支持拖拽文件和文件夹到目标列表。
- 展示目标名称、类型、来源路径、大小和当前状态。
- 支持移除单个目标、清空列表和去重。
- 添加目标失败时显示可理解的错误原因，不得让整个窗口崩溃。
- 执行按钮在没有有效目标时禁用。

### 4.2 参数设置

清理任务页面提供本次任务的参数选择：

- 清理级别：极速、日常、加强、深度。
- 文件夹根目录处理：删除根目录或仅清理目录内容。
- 执行前确认：允许用户关闭二次确认，但默认开启。
- 参数旁提供简短说明，明确清理强度越高，耗时通常越长。

### 4.3 确认、进度和结果

- 点击开始后显示确认对话框，列出目标数量、清理级别和不可逆提示。
- 执行中显示总进度、当前目标、已完成数量、失败数量和耗时。
- 提供停止或取消入口，并明确取消对当前目标的影响。
- 任务完成后显示成功、失败、跳过数量及总耗时。
- 结果页提供“返回新建任务”“查看清理记录”和“关闭结果”操作。
- 支持系统通知；通知关闭时，结果仍必须在窗口内完整展示。

## 5. 清理记录页面

记录页用于查看操作结果，不承担清理算法职责。

- 表格展示目标名称、来源位置、结果状态和执行时间。
- 支持按路径或目标名称搜索。
- 支持分页，默认每页 50 条，可选择 50、100、150、200 条。
- 支持跨页选择并批量删除记录。
- 删除记录前显示确认提示，删除后即时刷新表格。
- 没有记录或搜索无结果时显示明确的空状态。
- 新任务完成后，记录页可以自动刷新或显示新增记录提示。

## 6. 设置页面

### 6.1 清理设置

- 设置默认清理级别。
- 设置文件夹根目录默认处理方式。
- 设置是否在执行前显示确认对话框。
- 设置是否在任务完成后发送系统通知。

### 6.2 界面设置

- 提供浅色、深色或跟随系统主题的选项（若项目暂不支持主题切换，应保留扩展位置）。
- 提供语言选项或至少明确当前语言。
- 记住上次窗口大小、窗口位置和最近使用的页面。
- 窗口位置恢复时必须适配显示器断开、系统缩放变化和无效坐标。

### 6.3 系统设置

- 开机自动启动。
- Windows 资源管理器右键菜单。
- 最小化到托盘（如启用，需提供退出应用入口）。
- 关闭窗口时退出或最小化到托盘，由用户选择。

每项系统设置都应显示当前状态、作用说明和失败反馈。设置保存成功后立即生效，并持久化到应用数据目录。

## 7. Windows 资源管理器集成

Windows 版本可在当前用户范围内注册右键菜单：

```text
HKCU\Software\Classes\*\shell\FileShredder
HKCU\Software\Classes\Directory\shell\FileShredder
```

要求如下：

- 支持文件和文件夹。
- 从右键菜单启动时，打开主窗口并预填目标列表。
- 已有主窗口时复用当前实例，不创建重复窗口。
- 菜单安装、检测、更新图标和卸载操作必须幂等。
- 注册表操作失败时显示原因，并允许用户稍后重试。
- Windows 11 的“显示更多选项”行为按系统规则工作，在文档中说明入口位置。

## 8. 窗口与应用生命周期

- 使用单实例锁，重复启动只激活已有窗口。
- 第二次启动传入的文件路径应交给已有窗口并加入待处理列表。
- 主窗口关闭时按设置退出或隐藏到托盘。
- 应用退出前停止订阅、释放窗口资源和清理定时器。
- 系统休眠、恢复、显示器变化和 DPI 变化后，窗口仍保持可见且布局正常。
- 启动失败时记录错误并向用户显示可理解的提示。

## 9. 数据与隐私要求

- 设置、任务记录和用户导入的资源保存在 Electron 应用数据目录。
- 应用启动时以当前版本默认值补齐缺失设置，并兼容旧版本数据迁移。
- 用户删除自定义资源时，同时删除应用数据目录中的副本。
- 除用户主动选择的目标和设置外，不上传文件内容、路径或任务记录。
- 所有来自渲染进程的 IPC 参数都必须在主进程校验。
- 窗口启用 `contextIsolation`，关闭 `nodeIntegration`，并使用 sandbox。

## 10. 技术实现约束

- 主进程负责窗口管理、系统集成、文件对话框、持久化和通知。
- 预加载脚本只暴露最小化、类型明确的 IPC API。
- 渲染进程使用 Vue 3 和 TypeScript 实现页面、状态和交互。
- 界面组件应支持键盘操作、焦点移动和基本无障碍标签。
- 长任务不得阻塞渲染进程；进度通过事件或订阅机制更新。
- 页面状态与任务状态分离，切换页面不应中断正在运行的任务。

## 11. 构建和发布要求

- Windows 提供 x64 安装包，必要时保留 ia32 和 portable 构建。
- macOS 提供 x64 和 arm64 的 DMG 或 ZIP 构建。
- 安装器支持选择安装目录、创建桌面快捷方式和设置开机启动。
- 安装包使用统一应用名称、图标、版本号和卸载入口。
- 构建完成后只保留最终产物，清理临时文件和中间目录。
- 发布前执行类型检查、单元测试和应用构建检查。

建议命令：

```bash
npm run typecheck
npm test
npm run build:app
npm run build:win:x64
```

## 12. 验收标准

### 界面与交互

- 应用启动后显示标准桌面窗口，不显示桌宠、透明悬浮人物或气泡菜单。
- 窗口可以调整大小、最大化、最小化和恢复。
- 导航可以在清理任务、记录、设置和关于页面之间切换。
- 关键按钮在无目标、执行中、完成和失败状态下具有正确的启用状态。

### 系统集成

- 重复启动不会产生第二个主窗口。
- 从右键菜单传入的文件或文件夹会出现在已有窗口的待处理列表中。
- 开机启动和右键菜单可以在设置中启用、禁用和检测实际状态。
- 多显示器和屏幕缩放变化后，窗口不会跑到不可见区域。

### 数据与可靠性

- 设置和记录重启后仍然存在。
- 旧版本配置缺少字段时可以正常启动。
- IPC 传入非法参数时不会导致应用崩溃。
- 任务完成、失败或取消后，界面最终都会回到可继续操作的状态。

## 13. 从桌宠版迁移时需要移除的内容

以下能力不再作为产品需求：

- 透明无边框桌宠窗口。
- 桌宠拖拽手柄和人物位置锚点。
- 鼠标穿透透明区域。
- 气泡相对人物的左右、上下对齐设置。
- 桌宠形象切换、桌宠尺寸和桌宠图片上传。
- 桌宠动画状态与人物动作资源。

原桌宠代码可以在迁移阶段保留为历史实现，但新窗口版的页面、窗口管理器和设置模型不应继续依赖这些概念。
