## 1. 测试策略

### 1.1 分层

| 层          | 范围                                          | 手段                                    | 自动化 |
| ----------- | --------------------------------------------- | --------------------------------------- | ------ |
| L1 类型契约 | 全部 `src/**` 与 `electron/**` 的 TS/Vue 类型 | `npm run typecheck`（vue-tsc --noEmit） | 是     |
| L2 单元测试 | 纯函数与纯状态机（无 DOM、无 IPC）            | Vitest                                  | 是     |
| L3 交互验收 | 11 屏渲染与交互链路                           | 手工用例（`npm run dev` 启动应用）      | 否     |
| L4 构建检查 | 产物可构建、渲染与主进程各入口可打包          | `npm run build:app`                     | 是     |

### 1.2 可测试性设计约束（实现必须满足）

> 这是为了让 L2 能覆盖核心业务逻辑而强制的**代码组织约束**，实现时不得违背：

1. 所有可判定的业务规则必须落在 `src/utils/*` 或 `src/constants/*` 的**纯函数 / 纯常量**中，不得内联在 Vue 模板或组件方法里。
2. 任务状态机的**派生量**（当前步骤、结果三态、进度百分比、剩余时间）必须是可按输入计算的纯函数，禁止只能依赖 IPC 才能求值。
3. 组件内只做「取数据 → 调纯函数 → 渲染」，不在组件内写分支密集的业务换算。

### 1.3 覆盖目标

| 模块                     | 目标      | 说明                                       |
| ------------------------ | --------- | ------------------------------------------ |
| `src/utils/file.ts`      | 100% 分支 | 文件类型识别、大小格式化、名称提取         |
| `src/utils/format.ts`    | 100% 分支 | 时长、时间格式化                           |
| `src/constants/shred.ts` | 100% 取值 | 级别 / 阶段 / 结果语义映射                 |
| 任务状态派生             | 主要分支  | 步骤推进、结果三态判定                     |
| 记录筛选与分页           | 主要分支  | 四维筛选 + 分页切片                        |
| `electron/utils/bounds.ts` | 100% 分支 | 窗口恢复位置的可见性判定（多显示器 / 拔除 / 失效坐标） |
| Vue 组件                 | 不写单测  | 由 L3 手工验收覆盖；组件内不得承载业务换算 |

## 5. 已知限制

1. **L3 与 L4 自动化缺失**：Electron 界面验收依赖本地手工执行；本仓库未接入 Playwright / Spectron，因此 L3 用例为人工核对项。
2. **破坏性动作隔离**：涉及真实文件粉碎的用例（MT-SHRED-16 ~ 18）必须只在临时目录的测试文件上执行，禁止对用户数据目录操作。
3. **平台差异**：Windows 资源管理器右键菜单与开机自启相关用例（MT-SET-05 / MT-SET-07）仅在 Windows 有效。
4. **`cancelled` 语义**：`ShredSummary.cancelled === true` 且存在成功项时归入 05 态（部分成功），已在 UT-TASK-04 固化。
